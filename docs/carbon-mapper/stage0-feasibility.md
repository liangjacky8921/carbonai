## 官方数据与许可核验

- [Carbon Mapper 数据页](https://carbonmapper.org/data)介绍 CH₄、CO₂ 的卫星和航空离散观测，提供数据门户、Data API 与 STAC API；API 集成需通过数据门户注册。数据不是持续、秒级实时监测。
- [Data API 文档](https://api.carbonmapper.org/api/v1/docs)提供 plume/source 等地理数据，说明部分接口需要账户或授权范围、存在限流，并要求遵守使用条款及注明来源。尚未以项目账户验证所需接口的实际权限、字段与中国区域覆盖量。
- [2026-01-13 生效的使用条款](https://carbonmapper.org/terms)第 3 节以**非商业使用**为默认条件，商业使用须另行约定；要求清晰署名，向第三方再分发时有相同或实质相同的非商业与署名约束。是否适用于 CarbonAI 的网站及未来 SaaS 场景，需要按真实运营方式与数据提供方确认，不能仅以“公开可访问”推定可商用或可任意再分发。
- 同一条款第 3.2 节将利用其数据估计森林碳排放与移除通量排除在许可目的之外，因此不得将该数据直接接到现有“林地碳汇”估算中。第 5.1 节说明观测存在不确定性、覆盖空缺和发布延迟，单次观测不代表平均排放。其[产品指南](https://carbonmapper.org/articles/product-guide)区分 plume 与 source、观测时间、发布时间、排放速率和不确定性；这些字段必须分别展示，不得混成碳核算总量或企业台账。

## 最小集成方向（待许可门通过后评估）

1. 保留现有 Leaflet 地图和三个模式；在独立“外部卫星观测”层中只显示获准使用、经过质量筛选的真实记录。默认关闭，空结果明确显示“该范围/时段无可用观测”，不补造点位。
2. 后端以只读、限流、短期缓存方式访问官方 API；凭据只存服务端环境，不写入 Vue 包、Git 或文档。前端复用 `/api` 客户端，不新增 GIS 引擎或 React 应用。
3. 每个点位至少保留气体种类、观测时间（UTC/本地显示）、发布时间、原始记录 ID、传感器/产品、质量状态、数值与原始单位、不确定性、来源链接及“离散遥感观测”标签。字段缺失时显示缺失，不推导为实时值。
4. 点位叠加前验证官方坐标与高德底图显示坐标的转换和精度；地图上注明位置不确定性。外部观测不写入现有碳核算、排放因子或业务统计。
5. 保留数据来源及许可记录，正式软著源码材料只归集自研代码；外部数据和第三方组件不得描述为自有原创。保留真实 AI 辅助开发记录，不通过无意义改写“降低 AI 率”。

## 1. 审计结论

当前首页已经具备稳定的深石墨与低饱和碳绿设计系统、克制的 Aurora 背景、清晰的业务表述、响应式布局、键盘焦点和减少动画支持。它适合作为 3D 地球升级的基础，不需要重写首页。

H1 建议把绿色点云地球做成 Hero 内部的独立、懒加载视觉层，保留现有文字、CTA、业务章节和 CSS/SVG 后备。参考图只用于提取“点云大陆、空间轨道、边缘辉光、近黑留白”的构图语言，不直接作为背景或生产素材，也不复制其高亮度和密集粒子。

当前最需要控制的是首屏资源。浏览器实测首页资源传输约 487 KB，其中 Element Plus 共享包约 373 KB；新增 3D 代码若直接进入首屏同步路径，会明显扩大加载成本。因此，地球模块必须按需加载、限制 DPR 和点数，并在 WebGL 不可用、移动端和减少动画环境中降级。

| --- | ---: | --- | --- | --- | ---: | ---: |
| 1440 × 900 | 200 | 无 | 无 | 无 | 0 | 0 |
| 1280 × 800 | 200 | 无 | 无 | 无 | 0 | 0 |
| 768 × 900 | 200 | 无 | 无 | 进度已隐藏 | 0 | 0 |

- 1440 冷启动观测：DOMContentLoaded 约 489 ms，load 约 508 ms，8 个资源请求，约 487 KB 传输。该数值来自本机回环地址，只用于后续同环境对比，不能代表公网 LCP 或真实用户性能。
- 1280、768、390 的缓存后观测为约 124–141 ms，不作为冷启动指标。
- 当前首页请求的主要 JS：入口约 38.8 KB、Element Plus 约 373.1 KB、首页路由约 6.3 KB、备案组件约 0.9 KB，均为传输量近似值。
- `prefers-reduced-motion: reduce` 下，Hero 入场、Aurora ribbon 和网格动画的计算样式均为 `animation-name: none`。
- 当前首页没有 WebGL/Canvas 场景，因此尚无 3D 生命周期、显存释放或 WebGL 后备的实测结论。

### 已有优势

- 深石墨背景、低饱和碳绿和细线网格已经形成统一品牌基底。
- 首页采用纵向编辑式结构，避免了常见的三栏功能卡模板。
- 主标题、辅助文案和 CTA 的视觉主次明确。
- 页面已经提供背景动效暂停按钮，且有视口、页面可见性和减少动画控制。
- 功能描述保留“以业务页面和实际配置为准”等限定语，没有将示意图包装为真实监测结果。

### 需要在 H1 处理

1. 当前 Hero 右半区只有英文说明和抽象坐标轴，品牌记忆点不足；3D 地球应取代这一弱视觉，而不是覆盖文字区。
2. 当前 Aurora 在右侧已有较强亮区。地球加入后需降低 Aurora 对比度，避免两套主视觉争夺注意力。
3. 主标题在 390px 下占据较大纵向空间。移动端地球应放在文字后方或下方，并降低复杂度，不挤压 CTA。
4. 参考图的荧光密度偏高。生产实现应减少发光点、轨道和 bloom 感，维持 CarbonAI 已有的克制气质。
5. 当前 Hero 的“暂停背景动效”只能控制 Aurora；H1 应把地球旋转纳入同一控制语义，并确保按钮状态真实反映所有持续动画。

## 7. 3D 技术选型

### 推荐：Three.js 单库 + Vue 生命周期封装

当前需求只有一个可控 Hero 场景，直接使用 Three.js 更容易控制懒加载、渲染循环、几何缓存和资源释放，也避免为单一场景引入 TresJS 的额外运行依赖。建议在 H1 建立一个独立 `PointCloudGlobe.vue`，组件挂载时动态导入 Three.js，离开视口、页面隐藏或暂停时停止渲染，卸载时显式释放 geometry、material、texture 和 renderer。

### TresJS 备选

`@tresjs/core` 当前 npm 版本为 5.9.3，MIT，兼容 Vue 3.4+ 和 Three.js 0.133+；它还会带入 VueUse、Vue Devtools API、Radashi 和 Pointer Events 等依赖。若 H1 原型证明其构建增量与生命周期行为满足预算，可以采用；否则保持直接 Three.js 实现。

### 本阶段不建议引入

- **Lenis**：现有原生滚动、锚点、焦点和移动端手势工作正常，H1 地球不需要接管滚动。
- **Vue Bits**：npm 上名为 `vue-bits@1.1.1` 的包声明 Vue 2.6 peer dependency，不能把它当作 DavidHDev 当前 Vue 3 组件站点直接安装。现有 Aurora 已满足辅助氛围需要。
- **GSAP**：单个慢速自转、指针插值和入场可用 Three.js 与 CSS 完成，没有引入必要。
- **VueUse**：若采用直接 Three.js，当前需要的媒体查询、可见性和监听清理已经有轻量原生实现；不单独为此安装。

## 9. H1 实施边界与性能预算

- 地球必须是视觉示意，并提供对读屏器可理解的说明；不得暗示光点是实时排放监测点。
- 立即呈现 CSS/SVG 静态地球后备，WebGL 模块在 Hero 可见且浏览器空闲时懒加载。
- 初始预算：桌面点数不超过 40,000，移动端不超过 12,000；轨道线不超过 6 条；draw calls 尽量控制在 8 以内。
- DPR 上限：桌面 1.5，移动端 1.25；移动端可直接使用静态后备。
- 只使用慢速自转和轻微指针视差；不加入随机高频粒子、后处理 bloom 或滚动驱动镜头。
- `prefers-reduced-motion` 时停止自转和视差；页面隐藏、离开视口、手动暂停时停止 `requestAnimationFrame`。
- 增量预算：3D 路由块 gzip 尽量不超过 180 KB，地理数据 gzip 尽量不超过 100 KB；以 H0 同环境构建和浏览器数据为对照。
- H1 完成后必须验证：WebGL 不可用、上下文丢失、组件卸载、重复进入首页、尺寸变化、390px 和 768px 降级路径。

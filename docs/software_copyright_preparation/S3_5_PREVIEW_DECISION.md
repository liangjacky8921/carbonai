## 阻断项与最小解决方案

1. **认证权限**：通过 Carbon Mapper 官方数据门户获取适用于该研究用途的有效 Token，在本地或访问受控的环境中做限量联调；记录权限、账户附加条款及配额，不把凭据写入 Git、前端或日志。
2. **隔离环境**：提供独立于 `carbontool.cn` 的预览主机、域名、访问控制和回滚路径；确认预览不复用生产数据库或生产密钥。当前仓库没有现成的独立预览部署配置。
3. **许可与再分发**：明确预览访问者范围。若外部可访问，先落实网站级来源、学术引用、下游非商业与署名条件；必要时限制公开 API。个人/高校免费展示的事实须与实际运营主体和服务模式一致。
4. **缓存与配额**：确定浏览器/代理/CDN 的缓存响应策略、终止许可后的删除步骤；核对正式账户配额，并在多实例时采用共享限流或保持单实例且有访问控制。
5. **上线前回归**：满足上述门槛后，再在预览环境验证真实 CH₄/CO₂ 记录、缺失值、质量状态、桌面和手机、地图交互、异常降级、Token/日志检查以及原有 GIS、碳核算功能。

**是否建议进入 S4：否。**先完成上述条件，再重新作 GO/NO-GO 判断。本轮只新增此评估报告；未执行预览或生产部署。
